# Route and tracking maps

The booking/search route editor, rider and shared trip tracking, and driver dashboard share the same map controls, location and vehicle markers, and Midnight/Ice/Mint palette. The admin workspace does not embed a map.

- The booking editor keeps pickup, destination and stop labels distinct. Activate a visible marker to adjust the corresponding location, use the arrow keys to move the map, then confirm the new pin or press Escape to cancel. Asynchronous address lookups cannot replace a newer selection.
- On an active trip, the map maintains the trip route separately from the driver's approach to pickup. The map fits the relevant points on load and status transitions; it does not continually override manual pan or zoom as GPS positions change. The driver dashboard keeps its marker current as the vehicle type and availability change.
- Road routing keeps the existing provider/fallback sequence. When the road distance is unavailable, the map labels the approximate route instead of presenting it as a confirmed road route. Authoritative pricing is a separate server operation; see [Fare pricing](./fare-pricing.md).

Raster tiles use the [official OpenStreetMap tile URL](https://operations.osmfoundation.org/policies/tiles/) and keep attribution on the map. Next generates two same-origin MapLibre modules under `public/map-runtime/<installed version>/` from the lockfile-installed package. The worker and its relative shared import are kept together to avoid hashed module resolution issues. Assets are generated during normal Next dev/build and are not committed. This does not relax the existing Content Security Policy. For a standalone Next packaging workflow, copy the built `public/` tree as usual.

Tests can use fixed tile images, routes, and synthetic positions without contacting the tile or routing providers or accessing live GPS. The public tile service has no availability guarantee; production usage should follow its service policy.

## Address search pilot

`/api/places` no longer calls the OpenStreetMap Foundation's public Nominatim service, including for autocomplete. Set the **server-only** `GEOAPIFY_API_KEY` in a non-production environment first. Include both existing `UPSTASH_REDIS_REST_*` variables for a Vercel Preview: production-mode builds require a shared Redis budget and fail closed if it is unavailable. On local development builds without Redis the budget is process-local. The preview calls Geoapify for autocomplete, forward geocoding, and reverse lookup only. It does not change map tiles, route-distance providers, or fare calculations. A missing key preserves existing Photon-only lookup for low-volume use; its public instance is a demo, not a production SLA. A configured Geoapify pilot never spills failed searches onto the public Photon or Nominatim services.

Use a dedicated free Geoapify project/key with no paid upgrades or other consumers, and monitor its dashboard. This app currently permits at most 2,400 lookup attempts per UTC day and five per UTC second across instances backed by the same Redis namespace; provider-side limits still apply. Cached lookups expire after five minutes. Rate limits, outage, malformed responses, or absent Redis in production return a temporary unavailable response; no fabricated address is returned. Use the existing manual map pin when search is unavailable. OpenStreetMap attribution sits inside the open address-suggestion panel; the Geoapify link appears there when results come from Geoapify. The search forms have no standing credits line. Searches and reverse-lookup coordinates are sent to whichever provider is configured; use public landmarks for the pilot, not private rider addresses.

Try public pickup points such as Guwahati Railway Station, Paltan Bazaar, LGBI Airport, ISBT Guwahati, and local-market names in nearby towns; include Assamese typing, pin movement and reverse geocoding, and check that chosen coordinates are accurate before enabling production.

## WhatsApp login pilot

In a staging preview, select `WHATSAPP_PROVIDER=meta`, configure the existing Meta token and sending phone-number ID as server secrets, and set `WHATSAPP_OTP_TEMPLATE_NAME` to an approved **Authentication / Copy Code** template. Set `WHATSAPP_OTP_TEMPLATE_LANGUAGE` to its exact approved language code (defaults to `en_US`). The template body and copy-code button both receive the same server-issued code. Test only with a Meta test sender and allowlisted recipient before enrolling any real rider. Do not use a paid production sender or enable a paid fallback as part of the pilot. The PR does not alter the current provider selection, any deployment settings, or the in-app pickup PIN.
